## Business Problem

For a 50–100 person company, the accounts payable team typically processes hundreds to thousands of invoices per month manually — keying vendor names, amounts, line items, PO numbers, and GL codes into an ERP. According to the [Institute of Finance and Management (IOFM)](https://www.iofm.com/), the average cost to process a single invoice manually is **$12.88**, and the average cycle time is **17.4 days** from receipt to payment. Companies with fully automated AP processes pay just **$2.78 per invoice** and close in **3.1 days**.

The manual burden falls on 1–3 AP staff who spend 60–70% of their time on data entry, chasing approvals via email, and resolving mismatches between invoices and purchase orders. This creates late-payment penalties, missed early-payment discounts (typically 1–2% of invoice value), and strained vendor relationships. Exception rates average 22% with manual handling versus 9% with automation.

---

## Automation Overview

An AI invoice processing pipeline ingests incoming invoices (PDF, image, or email attachment), extracts structured data using OCR combined with a large language model, performs a three-way match against purchase orders and goods receipts in the ERP, routes exceptions to the right approver, and posts confirmed invoices directly to the accounting system. The full loop — from email receipt to ERP posting — runs in minutes rather than days for straight-through invoices.

## Workflow Stages

### Stage 1: Document Ingestion

| | |
|---|---|
| **Input** | PDF/image invoices arriving via email, vendor portal, or scan |
| **Process** | Automated mailbox monitoring (e.g., Make.com watching an AP inbox) captures attachments and pushes them to the extraction pipeline |
| **Output** | Raw invoice file queued for extraction with metadata (received timestamp, sender) |

### Stage 2: Data Extraction

| | |
|---|---|
| **Input** | Raw invoice file (PDF or image) |
| **Process** | Azure Document Intelligence or Nanonets applies pre-trained invoice models to extract vendor name, invoice number, date, line items, unit prices, tax, total, and payment terms; an LLM resolves ambiguous fields |
| **Output** | Structured JSON: `{vendor, invoice_no, date, line_items[], total, currency, payment_terms}` |

### Stage 3: Three-Way Match & Validation

| | |
|---|---|
| **Input** | Extracted invoice JSON + ERP purchase order + goods receipt record |
| **Process** | Automated comparison of invoice total vs. PO amount and received quantity; tolerance rules flag discrepancies >2%; duplicate invoice check runs against historical records |
| **Output** | Match result: Approved (straight-through) / Exception (routed for human review) |

### Stage 4: Approval Routing

| | |
|---|---|
| **Input** | Exception invoices with mismatch detail |
| **Process** | Rule-based routing sends invoice + diff summary to the correct approver via Slack or email; reminder escalation after 24 hours of inactivity |
| **Output** | Approval decision logged with timestamp and approver name |

### Stage 5: ERP Posting & Payment Scheduling

| | |
|---|---|
| **Input** | Approved invoice record |
| **Process** | Validated invoice auto-posted to QuickBooks / NetSuite / Xero via API; payment scheduled per terms (net-30, early-pay discount applied if applicable) |
| **Output** | Posted AP entry, payment scheduled, vendor confirmation sent |

## Implementation Steps

1. **Audit current state** — map the existing AP process: volume per month, average invoice types, current tools, exception rate, and cost per invoice. Establishes the baseline for ROI calculation.
2. **Set up a dedicated AP inbox** — create `ap@company.com` and configure Make.com (or Zapier) to watch it and push attachments to the extraction API automatically.
3. **Configure the extraction model** — connect Nanonets or Azure Document Intelligence; upload 20–50 sample invoices to tune the model to your vendor formats; validate field accuracy reaches ≥95% before going live.
4. **Build the three-way match logic** — write matching rules in Make.com or a lightweight Python script: compare extracted invoice total against ERP PO amount within a configurable tolerance (e.g., ±2%); flag line-item discrepancies.
5. **Connect to the ERP** — use the QuickBooks/Xero/NetSuite API to auto-post approved invoices to the correct GL account and cost centre; test with 10 live invoices before full rollout.
6. **Configure approval routing** — define rules (e.g., invoices >$5k require CFO approval; exceptions route to the PO owner); integrate with Slack or email for approver notifications with one-click approve/reject.
7. **Run a 2-week parallel pilot** — process real invoices through both the old manual flow and the new pipeline simultaneously; compare results and fix edge cases before cutting over.
8. **Go live and monitor** — turn off manual processing; track straight-through rate, exception rate, and cycle time weekly for the first month; retrain the extraction model on any new vendor formats encountered.

## Challenges & Mitigations

| Challenge | Mitigation Strategy |
|---|---|
| Vendor format variability — invoices arrive in hundreds of different layouts | Use a pre-trained model (Nanonets/Rossum) rather than template-based OCR; both handle novel formats via deep learning. Allocate 2–3 weeks to train on your top 20 vendor formats |
| Low-quality scans and handwritten invoices reducing extraction accuracy | Set a confidence threshold (e.g., 90%); route low-confidence extractions to human review automatically rather than posting bad data to ERP |
| ERP integration complexity — custom GL codes, cost centres, tax rules | Build the ERP integration on a separate phase; use Make.com's native QuickBooks/Xero connectors to avoid custom API work initially |
| Staff resistance / job security concerns | Reframe as reallocation: AP staff move from data entry to exception handling, vendor relationship management, and cash flow analysis |
| Duplicate invoice detection across periods | Maintain a hash index of processed invoice numbers and totals; flag any match within a rolling 90-day window for human review |
